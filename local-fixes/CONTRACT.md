# Promote contract

- **Names:** `node local-fixes/apply.mjs`, `node local-fixes/activate.mjs`, `node local-fixes/verify.mjs`; all share `pipeline.mjs` so no check can pass in one entrypoint and fail in another.
- **Purpose:** stage an official squeez release, activate it without overwriting a running executable, and detect drift in the owner's carried fixes. No compiler, installer or squeez subcommand is ever run.
- **Host and dependencies:** Windows x64, Node >= 22, authenticated `gh`, Windows `curl.exe`, HTTPS access to the GitHub release API and assets, and the release tag present in this repository for `activate`. No npm dependencies.
- **Inputs:** `apply [--dry-run | --apply] [--version vX.Y.Z]`; `activate [--dry-run | --apply] --version vX.Y.Z` (required); `verify` takes none. The default is dry-run. Only strict `vX.Y.Z` release tags; unknown or duplicate flags fail.
- **Outputs:** `PASS`/`FAIL` lines, stage path, SHA-256 values and backup paths; `verify` ends with `N pass / M fail`. Exit 0 on success, 1 on any failure. No file contents, child-process output, settings values or secrets are printed.
- **Writes:** dry-run and `verify` write nothing. `apply --apply` writes `staged/squeez-vX.Y.Z.exe` and reinstalls the owner plugin. `activate --apply` renames the live binary aside, writes the staged bytes in its place, refreshes the `policy.releaseAssets` files and writes `installed.json`. Every overwritten file is backed up first (`.bak-squeez-promote-<UTC>`, binary `.bak-squeez-activate-<UTC>`); identical files are left untouched.
- **Protected (check-only):** `~/.claude/settings.json`, Codex `hooks.json` and `config.toml`, all six per-host `config.ini`, the owner hooks and the Codex user-hook scripts. Invariants run fail-fast before any download or activation, and again after the plugin install. Drift aborts; repair needs a separate owner decision. Codex expectations follow `policy.codex.hooksMode` (`off` or `owner`).
- **Time:** each run has an 18-second budget; external commands receive the remainder. A network timeout fails rather than retries.
- **Integrity:** strict upstream repository, tag and asset URL; asset size at most 64 MB; the published SHA-256 is mandatory for download and the staged bytes must equal it again at activation; PE headers are validated and the subsystem must be 3. The PE is never rewritten.
- **Tests:** `node --test local-fixes/pipeline.test.mjs` (43 tests on temporary fixtures; never touches live files). The installed plugin's 9 tests exercise pure helpers only. Markers and tests cannot prove real WSL process termination or runtime compatibility of every host loader.
- **Failure model:** no transaction across files. Activation restores the previous binary if writing the new one fails; any later failure stops with backups in place and their paths printed.
- **Baseline 2026-09-30:** live binary is the official v1.48.10 asset, SHA-256 `875a98cd7e29fff13e4b7c33ca1d40af774d1eb7d77d691b8c6db84c01130ec7`, subsystem 3; `verify` 29 pass / 0 fail; Codex hooks off by owner decision (X-74, X-119).

Selected approach: one shared module with pure, fixture-tested checks, and activation by rename-then-write, because Windows allows renaming a running image but not overwriting it. Rejected: independent scripts duplicating invariant logic, retry loops around a locked executable, and reusing squeez's own setup/update machinery, which rewrites owner registrations (X-19, X-118).
